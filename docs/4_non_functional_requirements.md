## Нефункциональные требования

1. Безопасность
| ID | Требование | Метрика/условие | Целевое значение |
| --- | --- | --- | --- |
| NFR-1 | Доступ к функции должен быть предоставлен только авторизованному пользователю | Доступ к функции | Только для авторизованного клиента банка N |
| NFR-2 | Персональные данные и реквизиты операции должны передаваться по защищенному каналу | Протокол | TLS 1.2 |
| NFR-3 | Система должна логировать ключевые события операции для аудита | Логирование | Фиксируются создание, подтверждение, изменение статуса, ошибка перевода |
| NFR-4 | Система не должна раскрывать персональные данные получателя в интерфейсе и логах | Отображение в UI | Номер телефона и ФИО получателя отображаются в маскированном виде |
| NFR-5 | Подтверждение операции должно быть защищено от повторного использования запроса | Идемпотентность | Повторный запрос с тем же ключом идемпотентности не приводит к повторному списанию |

2. Надежность
| ID | Требование | Метрика/условие | Целевое значение |
| --- | --- | --- | --- |
| NFR-6 | Допустимый уровень потери данных при сбое | RPO | Не более n % |
| NFR-7 | Статус операции должен сохраняться и быть доступен для последующего просмотра | Durability | n % подтвержденных операций |


3. Производительность
| ID | Требование | Метрика/условие | Целевое значение |
| --- | --- | --- | --- |
| NFR-8 | Ответ на проверку лимитов и создание перевода должен возвращаться в пределах заданного SLA | p95 | Не более n мс |
| NFR-9 | Доля ошибок при создании перевода | Error rate | Не более n % в сутки |

4. Удобство использования
| ID | Требование | Метрика/условие | Целевое значение |
| --- | --- | --- | --- |
| NFR-10 | Понятность сообщений об ошибках | Пользовательская оценка | Сообщение содержит причину и последующие действия |
| NFR-11 | Количество шагов в основном сценарии | Количество экранов | Не более n экранов от выбора функции до подтверждения |

5. Совместимость
| ID | Требование | Метрика/условие |
| --- | --- | --- |
| NFR-12 | Версионирование API | API должен использовать версионирование (/api/v1) |
| NFR-13 | Обратная совместимость | Изменения API не должны ломать текущую версию |
| NFR-14 | Документация API | Контракт должен быть описан в OpenAPI |
